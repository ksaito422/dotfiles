# コミット

## 分割単位

1コミットは独立して revert できる1つの意図に対応させる。ファイル数ではなく、その変更だけを取り消す場面があるかで判断する。

- 別々のレビュー指摘、目的の異なる修正、マイグレーション、本題と無関係な自動整形は分ける。同じ修正で解消する指摘はまとめてよい。
- 1つの意図を成立させる実装と呼び出し側などはまとめる。
- TDD の失敗するテストと実装は別コミットにする。詳細は [git_checkpoints.md](../tdd/references/git_checkpoints.md) を参照する。
- 1単位ずつ修正・確認・コミットを済ませてから次の単位に進む。

## ステージとメッセージの確認

`git status --short` と差分で対象を確認し、`git add <対象パス>` でステージする。
`git diff --cached` で関連する変更だけが含まれ、機密情報や不要な生成物が入っていないことを確認する。
`git add -A` / `git add .` / `git commit -am` は、対象全体が1つの意図に収まると確認できる場合だけ使う。
`git commit -am` は未追跡ファイルを追加しない。コミット対象に新規ファイルがある場合は、先に `git add <対象パス>` で明示的にステージし、ステージ済み差分に含まれることを確認する。無関係な未追跡ファイルは取り込まない。

メッセージは `<type>[optional scope]: <description>` とし、コミット前に内容を確認する。

- type は `feat` / `fix` / `docs` / `style` / `refactor` / `test` / `chore`。
- タイトルは50文字以内。技術的変更は英語、業務機能・日本語UIの変更は日本語を推奨する。
- 背景や理由が必要なら日本語の本文を加える。差分で分かるファイル一覧は繰り返さない。
- 関連チケットがある場合は番号を記載する。

確認したメッセージで `git commit` を実行し、結果を確認する。

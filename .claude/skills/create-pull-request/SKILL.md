# Pull Request 作成

## 対象と前提

- ユーザーが指定したベースブランチを使い、指定がなければ分岐元ととする。作業対象のブランチとベースを混同しない。
- `git status`、ブランチ名、ベースとの差分・コミットを確認する。対象変更を [commit](../commit/SKILL.md) に従ってコミットする。
- コミット・プッシュの許可は会話と実行環境の規約に従う。既に許可された操作の確認を繰り返さない。対象が不明な未コミット変更は取り込まない。
- リモートへプッシュし、リモートの head がローカルの最終コミットと一致することを確認してから、本文準備と `gh pr create` に進む。
- PRは特に指定がない限り、Draftで作成する。

## タイトルと本文

実行環境のPR本文作成スキルに従ってタイトル・本文を準備する。テンプレートの読み込みと構造確認も同スキルで行う。
本文は今回作成する一時ファイルに保存する。ユーザーの既存ファイルを上書きしない。

## 作成と確認

同じ head/base の PR が既に存在しないか確認し、重複作成を避ける。

作成成功後、今回自分が作成した一時ファイルだけを削除し、PR の URL を報告する。

## セルフレビュー

- Claude Code の実装タスクでは、リモートへのプッシュ・PR作成後、 [completion-gate](../completion-gate/SKILL.md) の通過を確認する。未通過なら実行し、通過済みなら再実行しない。
- ゲート通過後（適用対象外なら対象変更のコミット後）に `git status` と最終コミットを確認する。ゲートで追加された修正コミットも含めて、再度リモートへプッシュする。このときDraft状態のPRであれば、 `git rebase` を許可する。

## 完了基準チェックリスト

- [ ] 未コミットの変更がローカルに残っていない
- [ ] すべてのコミットをリモートにプッシュした
- [ ] PRを作成し、descriptionを埋めた
- [ ] セルフレビューを実行した
